# ChatGPT 网页中转站

给团队共用一套 ChatGPT 登录态：**使用者零安装**，打开一个内网地址就能用 ——
不用各自注册账号、不用各自准备网络环境，也不用把谁的登录态交出去。

转发由服务器连着一台已登录的 Chrome 完成，同事那边只需要一个浏览器。

## 能做什么

| | |
|---|---|
| **对话** | 写下的内容送进 ChatGPT 里指定的一个项目，回复**边写边流回**页面，不用等整段写完 |
| **文件上传** | 点「＋ 附件」选文件、直接把文件拖进页面，或者粘贴一张截图 |
| **图片渲染** | 回复里生成的图、以及上传的图，都直接在页面上显示 |
| **文件下载** | 生成的文件与上传的附件都带下载块，点一下存到本地，**文件名保持原样** |
| **会话关联** | 每个会话对应 ChatGPT 里一个独立对话，随时回来接着聊，上下文完整延续 |

**共享的是登录态，隔离的是会话。** 大家共用同一套 ChatGPT 登录态 —— 这是"零安装"的代价，
也意味着同一时刻只能处理一条消息（详见下面的「维护消息」）。

而**会话在团队之间是完全隔离的**：每个人只看得到自己的会话，翻不到别人聊了什么、
传了什么文件。这不是前端藏起来而已 —— 服务端每条与会话相关的请求都会校验这个会话
属不属于当前登录的人，拿别人的会话 id 直接调接口一样是 404。

## 它是怎么工作的

```
同事的浏览器 ──HTTP──> 内网服务器 ──CDP──> 你自己的 Chrome ──> ChatGPT 项目页
```

服务器**不会另开一个浏览器**，而是连上你已经登录好的 Chrome，借用它的登录态。
你的登录、你的账号，全程不拷贝、不导出。

## 原理：为什么是「连接」而不是「启动」

两个 Chrome 的安全机制决定了这件事只能这么做：

1. **Chrome 127 起，cookie 用 App-Bound Encryption 加密**，密钥绑定浏览器安装位置。
   把 profile 拷到别的目录，登录态解不开 —— 实测验证过，拷过去的 cookie 一个都还原不了。
2. **Chrome 136 起，禁止对默认 profile 开启远程调试端口**（`--remote-debugging-port` 直接失效）。

剩下的官方通道就是 `chrome://inspect/#remote-debugging`：**你手动授权一次**，
Chrome 对本机开放调试端口，服务器连上去。这是 Google 自己设计的授权路径，不是绕过。

## 一次性准备：开启 Chrome 远程调试

1. Chrome 地址栏输入：

   ```
   chrome://inspect/#remote-debugging
   ```

2. 勾选允许远程调试（Chrome 会要求确认，必须你本人点）

3. 这个设置**会保留**，只需要做一次

**Chrome 必须保持运行。** 服务器靠连你的 Chrome 干活，关了就没法转发。
可以最小化，但别退出。建议把 Chrome 设为开机自启。

## 配置

配置写在 **`config.json`** 里 —— 这个文件不进版本库（各人的项目地址不一样）。
第一次先复制模板：

```bash
copy config.json.example config.json     # Windows
cp   config.json.example config.json     # Linux / macOS
```

| 键 | 必填 | 说明 |
|---|---|---|
| `CHATGPT_PROJECT_URL` | **是** | 要使用的 ChatGPT 项目地址。**所有对话都发生在这个项目的命名空间里**，别的项目和你自己的个人对话一律不碰。直接抄浏览器地址栏里 `/project` 之前的那一段，例如 `https://chatgpt.com/g/g-p-xxxxxxxx-我的项目` |
| `ADMIN_CONTACT` | 否 | 维护消息面板底部的联系方式，出问题时同事照这个找人。不配就不显示那一行 |
| `PORT` / `HOST` | 否 | 监听端口（默认 `8765`）与地址（默认 `0.0.0.0`） |

**同名环境变量优先于 `config.json`** —— 容器、CI、临时改端口这些场景用环境变量更顺手。

> 为什么填一整段地址而不是项目 id：项目 id（`g-p-...`）和后面的项目名是两截，
> 让人直接抄地址栏最不容易填错。

> **为什么配置不放 `start.bat` 里。** 两条实测出来的坑：`.bat` 必须是 CRLF 换行，
> 只有 LF 时 cmd 会按 512 字节分块解析、和行首失去同步，把每行开头当成命令去执行
> （整段注释都会被跑一遍）；换行修对之后，`set "VAR=中文…"` **仍然**会被解析器切坏,
> 连结尾引号都保不住（`echo 中文` 没事，赋值不行）。所以 `.bat` 退化成纯 ASCII 的启动器，
> 中文放 JSON 里 —— JSON 天生 UTF-8，没这些问题。

没配 `CHATGPT_PROJECT_URL` 时服务**照常启动**，但登录页和右上角信封会直接把原因和
要做的几步列出来 —— 不会闷不作声地收下消息然后什么都不发生。

## 跑起来

需要 Node.js（本项目在 v24 上开发）。

**Windows：双击 `start.bat`。** 它会自己检查 Node.js、首次自动装依赖、确认配置填好了，再启动。

其他平台：

```bash
npm install
npm start
```

启动时控制台会打出访问地址**和当前生效的项目地址**（配错了是这一步最常见的坑，所以直接印出来）。
然后浏览器打开它，**注册一个账号**（第一个用的人就是第一个账号）。

## 账号

- **账号即身份，不能重复。** 全角/半角、英文大小写视为同一个账号（`ＡＢＣ` 和 `abc` 是同一个）。
- **密码由你首次注册时设定，之后登录必须匹配。** 密码本身不要求强度。
- **密码没有找回通道。** 忘了就进不去了，注册时要输两遍就是防这个。
- **会话在团队之间隔离**：每人只看得到自己的会话与历史，互相翻不到。

> ⚠️ **`data/users.json` 请定期备份。** 账号表只在这一个文件里，丢了等于全员锁死
> —— 历史还在，但再也对应不上任何人。

## 会话

每个人可以有多个会话。**每个会话对应 ChatGPT 里一个独立对话**，绑定关系由服务器记住。

- **回到历史会话继续聊**：在左边点开任何一个旧会话，写新消息，
  这条消息会被送回 ChatGPT 里**对应的那个老对话**，上下文完整延续。
- **新建会话**：点左上角「+ 新建」，然后写下第一句 —— 会在项目下开一个全新的 ChatGPT 对话。
  不会立刻建空会话，所以不会积一堆没用的。
- **清空记录**：只删中转站这边的记录，ChatGPT 那边的对话不受影响。
- **删除会话**（鼠标移到会话上出现 ×）：**两边一起删** —— 中转的记录和 ChatGPT 里对应的对话
  都会删掉，不可撤销，删之前会跟你确认。如果 ChatGPT 那边本来就已经没了，会当作正常情况，
  不会报错打断你。

发出去之后，消息流末尾会出现一个朱红小点加「正在思考…」；如果是在排队等别人，
会显示「排队中，等待前面的消息…」——这两种等待时间差很多，所以分开显示。

**回复是边写边出来的。** 正文一落笔就开始显示在页面上，末尾跟一根闪烁的朱红竖线，
不用等整段写完。文字写完之后，服务器还要再花几秒去取图片与生成的文件，
这期间正文已经可以读了，竖线还在闪就是在忙这件事。

**按键**：输入框里 **Enter 直接发送**，**Shift + Enter 换行**（写长文用）。
用中文输入法时，选词/上屏的那个 Enter 不会被当成发送 —— 可以放心用拼音打字。

## 维护消息（右上角信封）

服务器连不上、登录过期、被风控这类故障，都会自动出现在右上角的信封里，**全体可见**
——因为大家共用同一个浏览器，故障对所有人是一样的。里面**带着排查步骤**，不用去翻文档。

有一个提示值得先知道：**大家共用同一个 ChatGPT 登录态，所以同一时刻只能处理一条消息。**
每人发言前，服务器需要把页面切到你的会话，大约几秒。人多时会排队，
顶栏会如实显示「排队中，前面还有 N 条」。

### 反馈

面板底部有一个「反馈」按钮。点了之后，**当时面板上的那条维护消息会被原样存档**
（状态、说明、排查步骤、最近的事件记录），加上是谁、什么时候。

存档在 `data/feedback/<日期>.log`，一天一个文件。管理员照着这个就能知道
同事当时到底遇到了什么，不用靠复述。

按钮点过就会置灰，避免同一条被反复提交；服务器状态变了会自动恢复成可点。

## 上传文件

三种给法都行：

- 点输入框那一行的 **「＋ 附件」** 选文件
- 把文件**直接拖进页面**任意位置（拖动时输入框会浮出一圈朱红虚线，告诉你落点）
- **粘贴**（Ctrl + V）—— 截图、从别处复制的图片文件都可以

选好的文件排在输入框上方，点它右上角的 × 可以撤掉。**不写字、只发文件也可以**，
这种会话的标题会用文件名兜底，免得会话栏里是一排认不出的「新会话」。

上限：**一条消息最多 6 个附件、合计 25 MB**。超了会当场弹提示，不会静默丢掉。

> 上传的**图片**直接显示在对话里；其余文件（xlsx、pdf、zip…）显示成下载块。
> ChatGPT 那边看到的是**你原本的文件名**，不是服务器上的存盘名。

## 回复里的图片与文件

ChatGPT 回复里的**图片**（生成的图、图表）会被下载到服务器并在页面里直接显示；
**生成的文件**（CSV、xlsx、docx、zip…）会显示成一个下载块，点「下载」就能存到本地。

同事都不需要登录 ChatGPT —— 服务器用自己那份登录态把它们取回来再转发。

> 两点要知道：
> - **生成图片比较慢**，通常要 1–2 分钟，期间顶栏会显示「正在生成…」，属正常。
> - 取这些东西要在服务器上多跑一次请求，个别文件取不到时，回复里会出现一行朱红提示
>   告诉你少了几个，不会静默消失。

## 实时更新

页面和服务之间是**长连接推送**（SSE），状态、会话列表、新消息、维护消息都是服务端主动推过来的，
不需要刷页。别人发消息、或者服务器和 Chrome 断了，你这边会立刻看到。

断线会自动重连；如果登录态过期了，会自动弹回登录页，不会在后台反复重试。

## 内网访问

服务默认监听 `0.0.0.0:8765`。同事用这台机器的内网 IP 访问：

```
http://<这台机器的内网IP>:8765
```

查内网 IP：`ipconfig`（找 IPv4 地址）。

**同事访问不了**，多半是 Windows 防火墙拦了。放行一次（需管理员权限）：

```powershell
netsh advfirewall firewall add rule name="ChatGPT 中转站" dir=in action=allow protocol=TCP localport=8765
```

改端口：`set PORT=9000 && npm start`。

## 常见问题

### 顶栏显示「连不上你的 Chrome」

1. Chrome 开着吗？（关了就会这样）
2. `chrome://inspect/#remote-debugging` 那个勾还在吗？Chrome 大版本更新后偶尔会重置
3. 都没问题就重启服务

### 显示「ChatGPT 登录已过期」

在**你自己的 Chrome** 里重新登录 ChatGPT 即可，不用重启服务 —— 服务器每 5 秒检查一次，会自动恢复。

### 显示「需人工验证」

Cloudflare 弹了验证。在**你的 Chrome** 里打开 ChatGPT 手动过一次。

### 服务会不会动我自己的 ChatGPT 标签页？

**不会。** 服务只操作那个项目命名空间下的标签页（`chatgpt.com/g/g-p-<项目 id>-<项目名>/…`），
你自己在 `chatgpt.com/c/…` 的私人对话不会被占用。退出服务也不会关你的浏览器。

### 数据都在哪

| 路径 | 内容 |
|---|---|
| `data/users.json` | 账号表（**要备份**） |
| `data/secret.key` | 登录态签名密钥，删了全员要重新登录 |
| `data/users/<内部id>/` | 各人的会话与消息、图片与文件附件 |
| `data/notices.json` | 维护消息日志（站内右上角面板显示的） |
| `data/logs/<日期>.log` | **给开发者看的日志**，一天一个文件，见下 |
| `data/feedback/<日期>.log` | 同事点「反馈」时存下的维护消息快照 |
| `data/legacy/` | 改造前的旧数据，归档保留，程序不读 |

### 开发者日志

`data/logs/2026-09-15.log` 这种，一天一个文件，追加写。目前只记一件事：

**中转里的会话删掉了，但 ChatGPT 那边没删成功。** 这会在项目里留下一个没人管的对话，
需要人工去善后，所以单独记下来，写清是谁、哪个会话、远程地址、失败原因。

站内那个通知面板是给全体同事看服务器故障的，这类只有开发者能处理的事就没往里塞。

> 反过来的情况（ChatGPT 那边早就删了、中转还留着）属于正常，删的时候会直接放过，
> 既不报错也不记日志。

## 设计说明

- **界面**是浅色纸感风格，全站只有一处彩色（朱红），用来标示主操作与异常状态。
- **串行队列**：一个登录态的硬约束。队列保证不竞态，且如实显示排队位置。
- **确认框和提示都是页内自绘的，不用浏览器原生 confirm/alert。** 这不是审美选择：
  服务器那侧的 Playwright 连着同事这个 Chrome，挂的正是他正在用的默认上下文，
  而 Playwright 在没有 dialog 处理器时会**自动关掉**页面弹出的原生对话框。
  实测前台标签页里 `confirm()` 7 毫秒就返回 false，没有人点过 —— 用原生的话，
  点了删除会毫无反应，报错也一声不响。改动这块时别图省事换回原生。
- **"写完了没有"不能只看停止按钮。** 实测 ChatGPT 的 SPA 会让「停止回答」按钮卡住
  不换回发送态（重载页面才恢复），而那时回复其实早就写完了。所以停止按钮只能延长
  等待窗口，真正的硬信号是加载动画；光凭按钮判断会让每条回复都空等到 180 秒超时。
- **上传和消息走同一个请求。** 文件在浏览器里读成 base64，随发送一起交给服务器。
  没做"先传文件拿 id、再按 id 发消息"那套 —— 新会话的第一条消息要先把文件传到一个
  还不存在的会话上，等于凭空多出一个暂存区和一套过期回收，换来的只是请求体小一点。
- **传给 ChatGPT 的是内存里的字节，不是磁盘路径。** 服务器上的存盘名是随机串
  （防路径穿越），直接拿它去传，ChatGPT 那边和同事看到的就会是乱码文件名。
  Playwright 的 `setInputFiles` 支持直接给 `{name, buffer}`，原始名因此得以保留。
- **"附件挂好了没有"以卡片出现为准。** 实测附件卡片出现之后，DOM 结构在 10 秒内
  一个字节都不变（12 MB 的文件也一样），发送键全程可用、也没有 `aria-busy` 之类的
  状态位 —— 没有比"文件名出现在编辑器里"更可靠的信号了，之后再留一小段静默余量。

## 已知限制

- **Chrome 必须一直开着。** 这是「借用你现有登录」的固有代价。
- **同时只处理一条消息。** 要真正并发，得为每个使用者配独立的 ChatGPT 登录态。
- **密码过内网是明文**（http），请提醒同事**不要用常用密码**。
- **ChatGPT 项目下的对话会随会话数增长**。删中转会话会一并删掉对面的对话，所以正常使用不会
  无限堆积；但删得掉的是「对话」，项目页本身仍会随历史变长而变慢。
- **依赖 ChatGPT 网页结构。** 选择器写在 `chatgpt.js` 顶部的 `SEL` 里，每项都带备选。
  哪天改版导致失败，改这里即可。
- **附件上限 6 个 / 25 MB。** 文件是读成 base64 随消息一起发的，上限就卡在这里。
  要放大得同时改 `server.js` 的 `MAX_FILES` / `MAX_UPLOAD_BYTES` / `MAX_BODY_UPLOAD`
  和 `public/app.js` 里那两个常数（前端那份只为早点给反馈，服务端才是权威）。
